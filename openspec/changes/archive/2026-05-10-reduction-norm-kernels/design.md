## Context

`packages/gpu` ships device bootstrap, `createSimpleComputePipeline`, the `KernelRegistry`, and the registered `bootstrap.fill-pi` and `core.{matmul,add,mul,scale,gelu,transpose}` kernels (`gpu-bootstrap`, `core-wgsl-kernels` specs). `packages/tensor` exposes a functional surface (`createZeros`, `createFromArray`, `matmul`, `add`, `mul`, `scale`, `gelu`, `transpose`, `reshape`) that routes to those kernels via the `core.*` IDs (`tensor-bootstrap` spec). `docs/sequential-change-proposals.md` step 4 sequences **reduction / softmax / normalization (forward)** kernels next so that the autograd / model layers can later define forward passes through attention (which needs `softmax`) and the `TransformerBlock` (which needs `rmsnorm`).

`docs/project.md`'s required-kernel inventory pins `softmax` as a "stable 2-pass: max → exp → sum → normalize", `rmsnorm` as `y = x / sqrt(mean(x²) + ε) · γ`, and `reduce_sum` / `reduce_max` as building blocks. The numerical-stability section reiterates: subtract `max(scores)` before `exp()` to avoid `NaN`. This change implements those forward kernels exactly once at the lowest layer (`packages/gpu`) and defers the tensor / autograd wrapping to follow-up changes — same staging that worked for `core-wgsl-kernels` → `tensor-bootstrap`.

Constraints from existing specs:

- **`monorepo-skeleton`** still requires the root `lint → test → build-all` smoke to exit zero **without GPU hardware**, so any tests that hit the GPU through these new kernels must skip cleanly when no WebGPU adapter is available — same gating pattern as `gpu-bootstrap`, `core-wgsl-kernels`, and `tensor-bootstrap`.
- **`gpu-bootstrap`** registry semantics — duplicate-ID registration policy is unchanged. New IDs land alongside `core.*`; the `CORE_KERNEL_IDS` constant grows.
- **`docs/project.md` GPU-only stance** — production code paths fail at `GpuContext.create` when no adapter exists; this change does not add any CPU fallback.
- **Layering** — `packages/gpu` MUST NOT add upward dependencies and MUST NOT touch `packages/tensor` in this scope. The new dispatch helpers stay reachable from tensor in a separate change without renaming.

## Goals / Non-Goals

**Goals:**

- Land **forward** WGSL kernels for `reduce_sum`, `reduce_max`, `softmax`, and `rmsnorm`, plus matching CPU references and Vitest coverage that reuses the existing `describe.skipIf(!webgpuAvailable)` gate.
- Register them as `core.reduce_sum`, `core.reduce_max`, `core.softmax`, `core.rmsnorm` on the existing `KernelRegistry` via an extension to `registerCoreKernels` (same one-call wiring).
- Ship typed dispatch helpers (`dispatchReduceSum`, `dispatchReduceMax`, `dispatchSoftmax`, `dispatchRmsNorm`) with the same shape as the existing `dispatch*` family — `(ctx, registry, ...buffers, rows, cols, ...scalars)` — so a future tensor wrapper can call them without re-deriving uniform layouts.
- Keep softmax **numerically stable** (subtract per-row max before `exp`); reflect this in tests with at least one row of large-magnitude inputs that would overflow `f32` without the stability trick.
- Keep `rmsnorm` parameterized by `epsilon` (callers pass `1e-6` by default); both WGSL and CPU reference share that constant exactly.
- Keep the public surface of `packages/gpu` strictly additive — no breaking edits to existing exports, ID names, or dispatch signatures.

**Non-Goals:**

- **Backward kernels** for any of these ops. Autograd lives in step 5 and will define backward functions against the forward kernels added here.
- **`causal_mask`**. The sequencing doc explicitly suggests deferring it to a separate small change; mask requirements will be defined when attention forward starts to assemble.
- **Per-axis reductions other than row-wise on rank-2.** Full reductions can be expressed by reshaping to `[1, n]` from a future tensor wrapper. N-D reductions are out of scope.
- **Workgroup-shared parallel reductions** (e.g. butterfly-shuffle / shared-memory sum trees). The first implementation uses **one thread per row, sequential accumulation over `cols`**, mirroring the "naive matmul first" stance from `core-wgsl-kernels`. A perf pass will revisit.
- **Fused softmax that depends on `core.reduce_*`**. `softmax` is a **single fused dispatch** that does its own max + exp + sum + divide per row. The standalone `reduce_*` kernels exist because consumers (loss aggregation, gradient-norm computation, debugging) will want them.
- **Non-`f32` dtypes**, **broadcasting**, **strided / non-contiguous inputs**, **embedding**, **cross-entropy**, **optimizer kernels**, **edits to `packages/tensor`**, and **edits to `packages/autograd`** — all out of scope for this change.

## Decisions

| Decision                                                                                                                                                                                                                                                         | Rationale                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Row-wise on rank-2 contract for all four kernels.** Inputs are row-major `[rows, cols]`; `reduce_*` outputs `[rows]`; `softmax` outputs `[rows, cols]`; `rmsnorm` outputs `[rows, cols]` and accepts `gamma: [cols]`.                                          | Matches what the next consumers actually need — softmax over the last axis of attention scores `[batch_heads, seq, seq]` reshaped to `[N, seq]`, and rmsnorm per-token over `d_model`. Full reductions can be expressed by reshaping to `[1, n]` from the future tensor wrapper; no need to ship a separate "scalar-reduce" kernel.                                                                                                                                                 |
| **One thread per row in this scope.** Each thread loops over `cols` sequentially. Workgroup size `256`, dispatch `ceil(rows / 256)` workgroups.                                                                                                                  | Matches the existing `core-wgsl-kernels` simplicity (workgroup size 256, one thread per output element). Correctness-first; performance optimization (parallel reduction) is its own change.                                                                                                                                                                                                                                                                                        |
| **`softmax` is a single fused dispatch, not a chain of `reduce_max` → exp → `reduce_sum` → div.** Each thread does the textbook two-pass per row inside the shader.                                                                                              | Avoids an intermediate "row max" buffer allocation per softmax call; keeps softmax stability invariants entirely inside one shader so the next layer can call a single dispatch.                                                                                                                                                                                                                                                                                                    |
| **Standalone `reduce_sum` / `reduce_max` are still shipped** even though `softmax` does not call them.                                                                                                                                                           | Loss aggregation, gradient-norm computation, and debugging readbacks will need them. Sequencing doc lists them by name; landing them now keeps the next changes diff-focused on tensor / autograd wiring rather than new WGSL.                                                                                                                                                                                                                                                      |
| **`rmsnorm` epsilon is a uniform**, not a WGSL `const`. Caller passes it (default `1e-6`).                                                                                                                                                                       | `docs/project.md` pins `ε = 1e-6` but a uniform keeps experimentation cheap (e.g. trying `1e-5` for FP32 stability) without recompiling the shader. CPU reference takes the same parameter.                                                                                                                                                                                                                                                                                         |
| **`reduce_max` and `softmax` initialize their per-row max accumulator from `input[base]`** (the first element of the row), not from a `bitcast<f32>(0xff800000u)` `-Infinity` literal.                                                                           | Tint rejects `bitcast<f32>(0xff800000u)` with "value -inf cannot be represented as 'f32'", so the bitcast trick is a non-starter under the project's Dawn-based runtime. First-element init is the textbook equivalent and is safe because the dispatch helper rejects `cols <= 0` (no empty-row reads). The CPU reference still uses `Number.NEGATIVE_INFINITY` because TypeScript supports it natively; both implementations produce the same numeric result for any `cols >= 1`. |
| **Uniform layout follows the existing 16-byte vec4 pattern** from `core-wgsl-kernels` (`UNIFORM_BYTES = 16`). `reduce_*` and `softmax` pack `(rows: u32, cols: u32, _pad0: u32, _pad1: u32)`. `rmsnorm` packs `(rows: u32, cols: u32, epsilon: f32, _pad: u32)`. | Reuses `makeUniform`'s 16-byte allocator; no new uniform plumbing. Padding to 16 bytes satisfies WGSL `vec4` alignment without a new helper.                                                                                                                                                                                                                                                                                                                                        |
| **CPU references live in the existing `cpu-reference.ts`** as `cpuReduceSum`, `cpuReduceMax`, `cpuSoftmax(rows, cols, data)`, `cpuRmsNorm(rows, cols, data, gamma, epsilon)`.                                                                                    | Single file is still small enough to navigate; matches `cpuMatMul` / `cpuGelu` placement. Splitting only when the file exceeds a screen of code.                                                                                                                                                                                                                                                                                                                                    |
| **Dispatch helpers extend the existing `dispatch*` style** (`(ctx, registry, ...buffers, rows, cols, ...scalars)`) rather than introducing a new "row-wise dispatch" abstraction.                                                                                | Matches `dispatchMatMul` / `dispatchTranspose` shape. The future tensor wrapper passes `t.shape[0]`, `t.shape[1]` directly, mirroring how `tensor.matmul` already passes `M, N, K`.                                                                                                                                                                                                                                                                                                 |
| **Tests reuse `core-kernels.spec.ts` / `core-kernels.test-helpers.ts` infrastructure** rather than introducing a separate spec runner.                                                                                                                           | Keeps the GPU-gated `describe.skipIf(!webgpuAvailable)` pattern in one place; avoids duplicating the `GpuContext.create()` + `registerCoreKernels(...)` setup boilerplate. The new specs may live in `core-kernels.spec.ts` directly or in a sibling `reduction-norm-kernels.spec.ts` — pick whichever keeps the file under ~400 lines.                                                                                                                                             |
| **One numerical-stability test for softmax is mandatory.** A row with values `[1000, 1001, 999]` (or similar) MUST produce a finite output that matches the CPU reference within float tolerance.                                                                | `docs/project.md` Numerical Stability section calls this out explicitly; the test is the durable guard against a regression that swaps the two-pass back to a one-pass implementation.                                                                                                                                                                                                                                                                                              |

**Alternatives considered:**

- **Building softmax as `reduce_max` → `subtract+exp` → `reduce_sum` → `divide`** at the dispatch-helper level rather than fusing into one shader. Rejected: requires two intermediate buffers per call (per-row max, per-row sum), four dispatches per softmax, and pushes responsibility for the stability trick out of the shader and into the helper. The fused version is simpler and faster while staying naive (one thread per row).
- **Implementing N-D reductions now** (axis parameter, multi-axis reduce). Rejected: the consumers in the next two layers only need row-wise on rank-2; N-D belongs to a tensor-layer broadcasting / reduce-axis change with its own design.
- **Workgroup-shared parallel reduction inside softmax / `reduce_*`.** Rejected here: belongs in the perf hardening change. Naive first; profile later.
- **Hard-coding `ε = 1e-6` as a WGSL constant** in `rmsnorm`. Rejected: a uniform costs the same and keeps experiments cheap. Default value still surfaces from the dispatch helper signature.

## Risks / Trade-offs

- **[Risk] Per-row sequential loops on the GPU are slow for large `cols`.** Mitigation: the sequencing doc explicitly defers performance work to its own change; tests use small shapes (`cols ≤ 64` for most cases, one larger shape for stability). When attention shapes get realistic (`cols` in the thousands), a follow-up change replaces the loop with a workgroup-shared parallel reduction without touching dispatch-helper signatures.
- **[Risk] `softmax` numerical stability could regress** if a future contributor "simplifies" the fused two-pass into a one-pass. Mitigation: the large-magnitude row test asserts finite output, and a code comment in `softmax.wgsl` documents the two-pass requirement with a pointer to `docs/project.md`.
- **[Risk] `rmsnorm` epsilon as a uniform means callers can pass `0`** and divide by zero on a zero-norm row. Mitigation: documented in the dispatch-helper JSDoc; the default `1e-6` is provided in the helper signature (`epsilon = 1e-6`) and the CPU reference uses the same default.
- **[Risk] `reduce_*` row-wise contract is awkward for "reduce everything to a scalar".** Mitigation: documented; future tensor wrapper reshapes `[1, n]` and reads back a single-element vector. A dedicated scalar-reduce kernel can be added later without renaming `core.reduce_sum` / `core.reduce_max`.
- **[Risk] Adding four IDs to `CORE_KERNEL_IDS` grows the array consumed by `registerCoreKernels` registration tests.** Mitigation: the tests assert "every ID in `CORE_KERNEL_IDS` resolves to a pipeline" rather than the exact length; trivial to extend.

## Migration Plan

- **Deploy**: Add new WGSL files, loaders, dispatch helpers, CPU references, and Vitest specs. Extend `registerCoreKernels` so the four new IDs are registered alongside the existing six. No existing exports change. No consumers exist yet (`packages/tensor` does not import any of the new IDs in this change).
- **Rollback**: Revert `packages/gpu` commits; `tensor`, `autograd`, `model`, `training`, and `inference` are unaffected.

## Open Questions

- **Spec file split**: do the four new kernels live in `core-kernels.spec.ts` alongside the existing six, or in a sibling `reduction-norm-kernels.spec.ts`? Tasks should pick **one** based on file length after implementation; both are valid.
- **Dispatch-helper naming**: `dispatchReduceSum` vs `dispatchRowReduceSum`. Proposal uses the shorter form for parity with `dispatchMatMul` / `dispatchAdd`. If a future change adds non-row-wise reductions, those would land as `dispatchReduceSumAxis` (or similar) without renaming the row-wise default.
- **Whether to expose a `cpuRowReduce` higher-order helper** in `cpu-reference.ts` that takes a `(acc, x) => acc` reducer, then derive `cpuReduceSum` / `cpuReduceMax` from it. Proposal keeps two explicit functions for grep-friendliness; refactor is a 5-line cleanup if the file grows.
