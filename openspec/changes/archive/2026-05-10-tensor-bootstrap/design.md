## Context

`docs/project.md` positions **`packages/tensor`** as the second layer in the bottom-up stack (`gpu` → **`tensor`** → `autograd` → …) and pins three concrete shape commitments: a `Tensor` value backed by `Float32Array` (CPU view) and `GPUBuffer` (device storage), a small dispatch surface (`matmul`, `add`, `mul`, `gelu`, `softmax`, `transpose`, `reshape`, …), and **GPU-resident** data with host readback only for tests/logging/checkpoint paths. `docs/sequential-change-proposals.md` step 3 sequences this immediately after `core-wgsl-kernels`.

`docs/project.md` sketches an OO surface (`Tensor.zeros(shape)`, `tensor.matmul(other)`); this proposal deliberately picks a **functional** surface — plain `Tensor` records and free functions like `matmul(rt, a, b)` — because the agents-md guidance and project-wide preference is for **data structures and pure functions where possible**. The functional surface is trivially derivable from the OO one (and vice versa), so the doc divergence is intentional and small.

Today `packages/tensor/src/index.ts` is a marker-only stub. The `gpu` package now exports `GpuContext`, `KernelRegistry`, `createFloat32StorageBuffer`, `writeFloat32Buffer`, `readFloat32Buffer`, the `core.*` kernel IDs, and typed `dispatch*` helpers — exactly the leaf surface a `Tensor` record + ops module needs to wrap.

Constraints from existing specs:

- **`monorepo-skeleton`** still requires the root `lint → test → build-all` smoke to exit zero **without GPU hardware**, so any tests that hit the GPU through `Tensor` must skip cleanly when no WebGPU adapter is available — same gating pattern as `gpu-bootstrap` and `core-wgsl-kernels`.
- **`docs/project.md` GPU-only stance** (“fail loudly if no adapter”) applies to production code paths. Constructors / ops accept a `TensorRuntime` parameter that is itself constructed from a real `GpuContext`; if the caller has no GPU, they cannot build a runtime, and the failure is surfaced at `GpuContext.create` (not later in `tensor`).
- **Layering**: `packages/tensor` MUST NOT add upward dependencies; it MUST only depend on `@llm-transformer-diy/gpu` at runtime. A types-only `devDependency` on **`@webgpu/types`** is added so the global `GPUBuffer` resolves cleanly under `noUncheckedIndexedAccess` and the type-aware ESLint rules; this matches the existing `gpu` package's reliance on the same types (transitively via the runtime `webgpu` package) and does not pull WebGPU runtime code into tensor.

## Goals / Non-Goals

**Goals:**

- A small, **explicit `Tensor` record** that owns: `shape: readonly number[]`, `strides: readonly number[]` (row-major, contiguous), `dtype: 'f32'`, `device: 'gpu'`, `buffer: GPUBuffer`, `length: number` — matching the `TensorData` interface sketched in `docs/project.md`, but as a `readonly`-only `interface` (no class, no methods).
- A **`TensorRuntime` record** `{ ctx, registry }` threaded as the **first parameter** of every function that allocates or dispatches; **no global default**, no module-level mutable state, no setter / getter pair.
- An op surface implemented as **free functions** that **route to existing `core.*` kernels** with shape pre-checks done in TypeScript (no new WGSL):
  - `matmul`, `add`, `mul`, `scale`, `gelu`, `transpose` (rank-2 only) — each `(rt, ...inputs) => Tensor`.
  - `reshape(a, newShape) => Tensor` — **no runtime parameter**, metadata-only, contiguous in/out, element-count match.
- **Pure shape / predicate helpers** (`computeContiguousStrides`, `productOfShape`, `isContiguous`, `sameShape`, `assertRank`, `assertSameShape`) that take only plain data (numbers, arrays, `Tensor` records) and return values or throw — no GPU, no I/O, no `await`.
- **Numerical tests** that, when WebGPU is available, run a `createFromArray` → op → `toArray` round trip and compare to `cpuMatMul` / `cpuAdd` / `cpuMul` / `cpuScale` / `cpuGelu` / `cpuTranspose` from `@llm-transformer-diy/gpu`.
- A **public surface narrow enough** for autograd to wrap (e.g. `Variable = { tensor, grad, requiresGrad, creator }`) without re-exporting raw `GPUBuffer`s through user code in the next change.

**Non-Goals:**

- **Classes / methods on `Tensor`.** No `tensor.matmul(...)`, no `Tensor.zeros(...)` static factory, no `this`. The whole package is data + functions.
- **Any global / module-level mutable state**, including a default `TensorRuntime` singleton. Callers thread `rt` explicitly.
- **Autograd**: no `Variable`, no `requires_grad`, no graph nodes, no backward functions. (Step 5 in sequencing doc.)
- **Broadcasting** of any kind on `add` / `mul`. Equal-shape only; broadcast support is its own change.
- **Reductions, softmax, RMSNorm, embedding, cross-entropy** — these need new kernels; sequencing doc step 4+ owns them.
- **Random init kernels** (`randn`, `xavier`). Defer to a focused **tensor-init** change so that this diff stays free of new WGSL.
- **CPU device backend** or **non-`f32` dtypes**. Single-dtype, single-device scaffold only.
- **General N-D transpose**, **strided / non-contiguous tensors**, and **views beyond `reshape`** (no `slice`, no `permute`, no `expand`).
- **Buffer pooling**, **deferred / lazy execution**, **command-buffer batching**. Each op submits eagerly, mirroring the `dispatch*` helpers in `gpu`.

## Decisions

| Decision                                                                                                                                                                                                                            | Rationale                                                                                                                                                                                                                                                                |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **`Tensor` is a `readonly` interface, not a class.** No `prototype`, no methods, no `instanceof`-based behavior. Construction goes through free functions (`createZeros`, `createFromArray`) that return plain object literals.     | Matches the project preference for data + pure functions. Keeps the value cheap to clone in JSDoc/tests, easy to log, easy to wrap in a higher-layer record (`Variable { tensor, grad, … }`) without inheritance.                                                        |
| **Ops are free functions** in `ops.ts` with the signature `(rt: TensorRuntime, ...inputs) => Tensor`. **No method form**, no fluent chaining helper.                                                                                | Single source of truth for the public surface; eliminates the “method vs function” bikeshed. Chaining is done via plain composition (`gelu(rt, add(rt, x, b))`) which is grep-friendly and easy to refactor.                                                             |
| **`TensorRuntime` is threaded explicitly.** No `setDefaultTensorRuntime` / `getDefaultTensorRuntime`, no module-level `let currentRuntime`. Callers (tests, future autograd / training code) hold a single `rt` object and pass it. | No hidden state means tests don’t need `beforeAll` / `afterAll` cleanup; multiple concurrent runtimes (e.g. per-test or per-device) become trivial; pure functions stay easy to reason about.                                                                            |
| **`reshape(a, newShape)` takes no runtime** and returns a new `Tensor` record sharing `a.buffer`.                                                                                                                                   | Metadata-only transform — no allocation, no dispatch, no I/O. Forcing a runtime parameter would be a lie about what the function does.                                                                                                                                   |
| **Row-major contiguous strides only**, derived in `shape.ts` (`computeContiguousStrides(shape)`). `isContiguous(t)` is a pure predicate used by `reshape` and any future view function.                                             | Keeps invariants simple for this slice; matches matmul / transpose / elementwise contracts already documented in `core-wgsl-kernels`. Strided views are a separate change.                                                                                               |
| **All ops return a fresh output `Tensor`** with a freshly allocated `GPUBuffer`. **No in-place ops, no aliasing of inputs (except `reshape`, which documents buffer-sharing).**                                                     | Predictable semantics for the upcoming autograd graph; eliminates aliasing surprises. In-place / fused ops can come with the optimizer/training change.                                                                                                                  |
| **No internal buffer pool / cache.** Each op calls `createFloat32StorageBuffer`.                                                                                                                                                    | Sequencing doc explicitly defers buffer-pool tuning; pooling will sit behind the same free-function API once introduced (callers are unaffected).                                                                                                                        |
| **Errors thrown synchronously** from op functions on shape / rank / contiguity mismatches; readback (`toArray`) is the only `async` surface.                                                                                        | Matches the existing `dispatch*` helpers’ synchronous compute-pass submission. Readback is `async` because `mapAsync` is.                                                                                                                                                |
| **Lifecycle is a free `destroy(t)` function** that calls `t.buffer.destroy()`. **No internal “alive” flag**, no custom tracking — destroyed-buffer use surfaces through WebGPU’s own validation.                                    | Keeps `Tensor` strictly a data record. If we later need safer access patterns, a thin wrapper (e.g. an `Arena` that tracks ownership) can sit alongside without changing the data shape.                                                                                 |
| **Tests reuse `cpu*` references from `@llm-transformer-diy/gpu`** rather than duplicating CPU math.                                                                                                                                 | Single source of truth for GELU constants and matmul layout; avoids drift between `gpu` and `tensor` reference implementations.                                                                                                                                          |
| **`@webgpu/types` is a tensor `devDependency`** and is loaded via a `/// <reference types="@webgpu/types" />` directive at the top of `types.ts`.                                                                                   | Required so the `GPUBuffer` global resolves under tensor's strict type-aware ESLint rules. Pure-types package (no runtime), matches the allowed-dep spirit in `docs/project.md`. The runtime `webgpu` package stays scoped to `packages/gpu` per `gpu-bootstrap` design. |
| **Vitest `it.skipIf(!await probeWebGpu())` gating** on GPU integration specs (mirroring `core-kernels.spec.ts`).                                                                                                                    | Preserves `monorepo-skeleton` smoke; production code paths still surface failures at `GpuContext.create` when no adapter exists.                                                                                                                                         |

## Risks / Trade-offs

- **[Risk] Threading `rt` through every op is verbose** for callers that compose many ops. Mitigation: composition is still cheap (`gelu(rt, add(rt, x, b))`); if verbosity becomes painful for a real consumer (autograd), introducing a tiny `withRuntime(rt)` higher-order helper that returns pre-applied versions of each op is a 10-line follow-up that does not change the underlying API. The current scope refuses to ship the helper preemptively.
- **[Risk] Eager allocation per op leaks `GPUBuffer`s in long-running flows.** Mitigation: out-of-scope for this change, but document in the design that a future change will introduce pooling; tests call `destroy(t)` in cleanup helpers.
- **[Risk] `reshape` accepting only contiguous tensors will need to evolve once views land.** Mitigation: throw a clear error today (`'reshape: non-contiguous strides not supported in tensor-bootstrap'`) so callers get an actionable message rather than silent corruption.
- **[Risk] `destroy` without an alive-flag means use-after-free surfaces only as a WebGPU validation error.** Mitigation: documented behavior; tests assert that `toArray` rejects on a destroyed buffer (relying on Dawn’s validation) rather than us tracking a custom flag. If the validation message is unhelpful in practice, an opt-in `assertAlive(t)` helper can be added without changing the data shape.

## Migration Plan

- **Deploy**: Replace `packages/tensor/src/index.ts` exports with real types and re-exports from new modules. No consumers exist yet (autograd is still a stub), so no downstream migration required.
- **Rollback**: Revert `packages/tensor` commits; `gpu` is unaffected.

## Open Questions

- **Constructor naming.** Proposal uses `createZeros(rt, shape)` / `createFromArray(rt, data, shape)` to make “this allocates a GPU buffer” obvious in call sites. Alternative: shorter `zeros(rt, shape)` / `fromArray(rt, data, shape)` matching the docstring style in `docs/project.md`. Tasks should pick **one** consistent prefix and document the rejected form.
- **Module shape: one `ops.ts` vs per-op files.** Proposal puts all six ops in one `ops.ts` for discoverability while the surface is small. If autograd later wants to import each op alongside its backward function, splitting is cheap; do not pre-split now.
- **Public re-export of `cpu*` references** through `@llm-transformer-diy/tensor` for downstream test packages. Defer — autograd tests can import `cpu*` directly from `@llm-transformer-diy/gpu` without a re-export.
